# 延迟重放阶段记录

实验日期：2026-10-30。整理与核对日期：2026-11-02。日志目录名使用 UTC，不是本地时区。

本阶段实现了按相机时间戳选择历史帧的延迟中继，并完成 Ubuntu/ROS 2 Jazzy/Gazebo 仿真运行。最新 1 秒试验有操作者报告的方块接触，随后控制器触发视觉停车并持续发布零速度指令。本目录记录开发试验，尚不是同版本重复实验的成功率评估。

## 代码与条件

- 当前场景为房子、道路、白线和红方块，方块中心 X=4.0 m、Y=0；每轮机器人从原点向 +X 行驶。
- 当前速度设定 1.0 m/s、视觉阈值 0.4、`enable_goal_stop=false`、传感器超时 2.0 墙钟秒。场景与完整步骤见 [固定基线](../../docs/experiment-baseline.md)。
- 中继输入 `/camera/image_raw`，输出 `/attack/image_raw`。输出及控制器订阅使用 reliable、深度 1。
- 旧配置没有记录 `enable_goal_stop`，不能将缺失字段解释为 false。旧 0.5 秒和旧 1 秒日志保留原样，不与新版直接合并计算成功率。

## 最新 1 秒试验核对

源文件为该试次的两份 config.json、events.csv 和 frames.csv，均按原始字节归档。完整计算见 [审计 JSON](summaries/20261030T153945.096132Z.json)。

从首次 RUNNING 到首次 OBSTACLE_STOP，控制日志出现 47 个不同的图像时间戳，全部匹配中继输入时间戳。它们都处于 REPLAY，无匹配的缓冲重置。由输入时间戳减所选原始帧时间戳得到实际重放延迟 **1.022–1.353 仿真秒**，平均 **1.099447 秒**。平均值按不同输出图像时间戳等权，控制定时采样可能遗漏两次 tick 之间的图像回调，因此不代表所有收到的图像帧。

停车触发图像的输入时间为 9.142 s，历史内容时间为 8.118 s，重放延迟 **1.024 s**；控制采样时仿真时间 9.183 s，该内容年龄约 **1.065 s**。这与现实经过的墙钟时间不同。

以首次 OBSTACLE_STOP 为墙钟相对时间零点：

| 原始 events.csv 行号 | 相对墙钟时间 | 状态 | cmd_v (m/s) | odom_v (m/s) | 红色比例 |
|---:|---:|---|---:|---:|---:|
| 195 | -0.100586 s | RUNNING | 1.0 | -0.001640 | 0.391016 |
| 196 | 0 s | OBSTACLE_STOP | 0.0 | 0.209030 | 0.484722 |
| 197 | +0.099883 s | OBSTACLE_STOP | 0.0 | 0.027207 | 0.484722 |
| 199 | +0.301342 s | OBSTACLE_STOP | 0.0 | 0.0 | 0.484722 |

从停车采样起，后续 **17,185 条记录的 cmd_v 与 cmd_w 均为零**。约 0.301 墙钟秒后首次记录到 odom_v=0，之后记录值在 -0.001661 至 0 m/s。整个控制日志只有 RUNNING、OBSTACLE_STOP 两种状态，无 GOAL_REACHED、SENSOR_TIMEOUT 或 FAULT 切换。

停车前存在一条“仍指令前进但里程计速度接近零”的采样，与操作者报告的接触相符；它不能独立确定接触时刻或受阻持续时间。cmd_v/cmd_w 是控制器发布调用的记录，没有独立 `/cmd_vel` 录包。没有同步接触传感器、仿真真值净距或视频。

## 其他已审计日志

- [旧 0.5 秒试验](summaries/20261030T151809.464826Z.json)：36 个匹配时间戳，实际延迟 0.527–0.925 s、平均 0.627944 s；首次 OBSTACLE_STOP，后续 5,799 条指令均为零。原始配置确认速度为 1.0 m/s，0.5 是延迟秒数。
- [旧 1 秒试验](summaries/20261030T150208.755759Z.json)：41 个匹配时间戳，实际延迟 1.022–1.386 s、平均 1.094732 s。首次 GOAL_REACHED，后续 4,236 条指令均为零；状态后来变成 OBSTACLE_STOP，是此次修复“锁定首次停止原因”的动机。

## 离线复核

在仓库根目录使用 Python 3，无需 ROS：

```bash
python3 scripts/audit_replay_run.py \
  --baseline results/delay-replay-2026-10-30/runs/20261030T153945.096132Z \
  --relay results/delay-replay-2026-10-30/runs/20261030T153932.320958Z
```

更换两个 run ID 可复算其他配对。脚本只读取源日志，输出 JSON；每份审计 JSON 内列出四个原始文件的字节数和 SHA-256。出现重复输入时间戳时拒绝静默关联，需先按时钟重置划分会话。

## 当前边界与后续

本阶段证据支持“1 秒延迟重放条件下出现接触，随后视觉阈值触发主动停车”这一案例描述。下一阶段需补齐新版 0 秒原始日志，并在相同版本、场景、速度、阈值和终点设置下重复 0、0.5、1 秒试验；保留全部结果及与 run ID 对应的接触证据。当前不报告攻击成功率，也未实现 LiDAR 验证或防御。

[本地验证记录](validation/README.md)区分可在 Windows 执行的检查、缺少的 ROS/OpenCV 测试和操作者提供的 Ubuntu 实验日志。
